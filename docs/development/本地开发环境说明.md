# 本地开发环境说明

更新时间：2026-06-03

本文说明 Little Bear 交付版代码库的本地开发环境准备、启动顺序、常用命令和排障入口。本文只描述交付版可用的开发方式，不包含生产编排假设。

## 适用范围

本地开发环境包含：

- PostgreSQL：业务事实源、迁移、配置、任务、权限、日志。
- Redis：当前作为基础设施和 ServiceBootstrap 依赖接入，业务缓存能力仍按设计文档逐步落地。
- MinIO：原始文件、解析结果、清洗结果和 chunk 正文对象存储。
- Qdrant：向量索引和权限 payload。
- TEI embedding / rerank：本地真实联调模型服务。
- FastAPI API、Worker、普通用户查询前端、管理后台前端。

## 前置依赖

开发机需要具备：

- Python 3.12 或以上。
- Node.js 与 npm，仓库使用 npm workspaces。
- Docker 与 Docker Compose。
- 可访问本地端口：`5432`、`6379`、`9000`、`9001`、`6333`、`6334`、`8081`、`8082`、`8000`、`5173`、`5174`。

Python 依赖以 `pyproject.toml` 为准，前端依赖以根目录 `package.json` 和各 workspace 为准。

## 环境文件

生成本地环境文件：

```bash
make env
```

该命令会在 `.env` 不存在时复制 `.env.example`。

`.env` 只负责启动层、本地容器初始化、一次性 secret 写入和测试脚本参数。Redis、MinIO、Qdrant、embedding、rerank、LLM、检索策略、权限策略、缓存策略、限流策略和审计策略等业务配置不应直接从环境变量读取，必须通过初始化后的 active config 进入系统。

`.env.example` 已按使用阶段分组：

- 生产与开发都需要的运行配置：应用进程、数据库连接、setup 初始化、Secret Store、前端 API 地址和 Worker 运行参数。
- 一次性初始化后应删除的明文 Secret：仅用于初始化或手工写入 PostgreSQL secrets 表。
- 仅本地开发和测试使用的配置：Docker Compose 容器初始化、真实依赖集成测试、smoke 和查询回归参数。

常见本地启动层变量：

- `DATABASE_URL`
- `DATABASE_CONNECT_TIMEOUT_SECONDS`
- `DATABASE_POOL_SIZE`
- `DATABASE_POOL_MAX_OVERFLOW`
- `DATABASE_SSL_MODE`
- `APP_ENV`
- `SERVICE_NAME`
- `API_HOST`
- `API_PORT`
- `LOG_LEVEL`
- `SECRET_STORE_MASTER_KEY`

普通前端和管理后台开发服务器通过 Vite 代理 `/internal` 和 `/health` 到 `http://127.0.0.1:8000`，本地默认使用：

```text
VITE_API_BASE_URL=http://localhost:8000
```

## 启动顺序

推荐从仓库根目录执行。

1. 启动基础设施：

```bash
make up
```

2. 查看容器状态：

```bash
make ps
```

3. 执行数据库迁移：

```bash
make PYTHON=.venv/bin/python db-upgrade
```

4. 启动 API：

```bash
make PYTHON=.venv/bin/python api
```

5. 完成初始化。

首次空库启动后，系统进入 setup mode。此时只能访问 setup-state、setup-config-validations、setup-initialization 和生命周期允许的 healthcheck。初始化成功后必须存在 active config，否则普通业务 API 会被 ServiceBootstrap 拒绝。

6. 启动 Worker：

```bash
make PYTHON=.venv/bin/python worker
```

多个 Worker 可使用：

```bash
make PYTHON=.venv/bin/python worker-1
make PYTHON=.venv/bin/python worker-2
```

7. 启动普通用户前端：

```bash
make web
```

默认地址：`http://localhost:5173`

8. 启动管理后台：

```bash
make admin
```

默认地址：`http://localhost:5174`

## 本地初始化注意事项

初始化需要写入：

- 企业、部门和初始管理员。
- active config。
- Secret Store 中的 provider 密钥引用。
- ServiceBootstrap 可验证的外部依赖配置。

如果 API 登录时返回：

```text
SERVICE_BOOTSTRAP_UNAVAILABLE: service bootstrap is not ready
```

优先检查：

- Alembic 是否已经迁移到 head。
- 是否已经完成 setup 初始化。
- active config 是否存在且处于 active 状态。
- Secret Store master key 是否可用。
- Redis、MinIO、Qdrant、embedding、rerank、LLM 配置是否能通过 bootstrap 校验。

## Worker 开发说明

Worker 与 API 的区别：

- API 负责 HTTP 请求、权限校验、任务创建、状态查询和管理操作。
- Worker 负责领取导入 / 索引任务，执行 parse、clean、chunk、embed、draft index、publish 等后台阶段。

Worker 使用任务锁实现接管：

- `WORKER_ID` 为空时会使用自动 worker id。
- 多 Worker 通过 `locked_by` 和 `locked_until` 避免重复执行同一任务。
- 失败任务按实现中的 retry / recover 逻辑处理。

开发时不要让 Worker 调用 FastAPI route function，Worker 应使用模块 service/runtime。

## 前端本地开发说明

普通查询前端：

- 入口：`apps/web`
- 默认端口：`5173`
- API client 位于 `apps/web/src/api`
- 查询工作区以 `ChatWorkspace` 和 runtime composable 为核心。

管理后台前端：

- 入口：`apps/admin`
- 默认端口：`5174`
- API client 位于 `apps/admin/src/api`
- 功能页通过 feature registry 动态加载。
- 管理后台菜单可见性由后端用户权限和前端 capability provider 共同决定，但权限最终以后端校验为准。

## 常见故障

### 数据库不可用

现象：

```text
DATABASE_UNAVAILABLE
```

处理：

```bash
make ps
make logs
make PYTHON=.venv/bin/python db-current
```

确认 PostgreSQL 已启动并且 `.env` 中的连接信息正确。

### 初始化后仍无法登录

常见原因：

- active config 缺失。
- active config 依赖校验失败。
- Secret Store master key 与已加密 secret 不匹配。
- 业务依赖不可达。

处理顺序：

1. 查看 `/health/ready`。
2. 查看 API 日志中的 ServiceBootstrap 失败项。
3. 在管理后台或 setup 流程中修正配置。
4. 重新发布 active config。

### 导入任务一直 queued

通常是 Worker 未启动或无法领取任务。

处理：

```bash
make PYTHON=.venv/bin/python worker
```

如果多个 Worker 并行开发，使用不同 `WORKER_ID`。

### 查询降级

查询降级不是一定错误。常见原因：

- embedding provider 不可用，降级关键词检索。
- rerank provider 超时，使用融合分数。
- LLM 超时，返回检索结果和引用。
- citation 校验失败，抑制原答案并返回结构化说明。

需要结合查询日志、模型调用日志和检索诊断查看具体阶段。

## 开发边界

- 不要在 `.env` 中新增业务决策配置。
- 不要在 route 层直接访问 Qdrant、MinIO 或模型 provider。
- 不要用前端隐藏菜单代替后端权限控制。
- 不要把归档材料中的非交付设计直接当作交付版实现。
- 修改 API、权限、状态机、审计或配置 schema 时，必须同步更新 `docs/contracts/`。
