# 核心业务链路时序图

更新时间：2026-06-03

本文用时序图说明 Little Bear 当前核心业务链路。图中只保留关键调用、状态变化、权限校验、审计和降级点，不展开字段级细节。

## 1. 系统初始化链路

```mermaid
sequenceDiagram
    participant Admin as 初始化页面
    participant API as Setup Routes
    participant Setup as Setup Service
    participant Config as Config/Secret/Bootstrap
    participant PG as PostgreSQL
    participant Ext as MinIO/Qdrant/Redis/Model

    Admin->>API: 查询 setup-state
    API->>PG: 读取 system_state
    PG-->>API: initialized / bootstrap 状态
    API-->>Admin: 返回初始化状态

    Admin->>API: 提交初始化配置
    API->>Setup: validate + initialize
    Setup->>PG: 创建企业、部门、管理员、内置角色
    Setup->>PG: 写入 config_versions / system_configs / secrets
    Setup->>Config: 发布 active config
    Config->>Ext: 探测外部依赖
    Config->>PG: 写入 bootstrap 状态
    Setup->>PG: 写审计日志
    API-->>Admin: 初始化成功或结构化错误
```

关键状态：

- 未初始化时，只允许访问 setup 和健康检查相关接口。
- 初始化成功后必须存在 active config。
- initialized=true 但 active config 或关键依赖不可用时，普通业务 API 进入拒绝模式。

## 2. 登录鉴权链路

```mermaid
sequenceDiagram
    participant Client as Web/Admin
    participant API as Auth Routes
    participant Guard as SetupGuard
    participant Auth as Auth Service
    participant PG as PostgreSQL

    Client->>API: POST /internal/v1/sessions
    API->>Guard: 检查服务是否已 bootstrap
    Guard-->>API: ready 或 SERVICE_BOOTSTRAP_UNAVAILABLE
    API->>Auth: 校验用户名密码
    Auth->>PG: 读取 user / credential / role / department
    PG-->>Auth: 用户与权限事实
    Auth->>Auth: Argon2 校验密码，签发 PyJWT token
    Auth->>PG: 写 session/token 记录
    API-->>Client: access token / refresh token / 当前用户摘要
```

关键状态：

- 用户必须 active。
- 普通员工可登录普通查询前端，但不能进入管理后台。
- 管理后台菜单隐藏不作为权限边界；每个后端接口仍要做 scope 校验。

## 3. 文档导入链路

```mermaid
sequenceDiagram
    participant Admin as 管理后台
    participant API as Import Routes
    participant Import as Import Service
    participant Perm as Permission Guard
    participant Store as Object Storage
    participant PG as PostgreSQL
    participant Worker as Worker

    Admin->>API: 上传文档
    API->>Import: create_document_import
    Import->>Perm: 校验操作者可导入目标知识库/部门
    Import->>Store: 写入原始文件
    Import->>PG: 创建 document / document_version / import_job
    Import->>PG: 写导入审计
    API-->>Admin: 返回 queued import job

    Worker->>PG: claim_next_job FOR UPDATE SKIP LOCKED
    PG-->>Worker: job running + locked_by + locked_until
    Worker->>Import: advance_claimed_job
```

关键状态：

- 上传成功只代表任务创建成功，不代表文档已可查询。
- `import_jobs.status` 初始为 `queued`，Worker 领取后变为 `running`。
- Worker 通过 `locked_by` 和 `locked_until` 控制并发处理和锁接管。

## 4. 导入阶段与索引发布链路

```mermaid
sequenceDiagram
    participant Worker as Worker
    participant Runner as ImportStageRunner
    participant Store as Object Storage
    participant Index as Indexing Service
    participant Model as Embedding Provider
    participant Qdrant as Qdrant
    participant PG as PostgreSQL

    Worker->>Runner: stage=validate
    Runner->>PG: document.index_status=indexing

    Worker->>Runner: stage=parse
    Runner->>Store: 读取原始对象
    Runner->>Store: 写 parsed 派生对象
    Runner->>PG: document_version.status=parsed

    Worker->>Runner: stage=clean
    Runner->>Store: 写 cleaned 派生对象

    Worker->>Runner: stage=chunk
    Runner->>Store: 写 chunk 完整正文对象
    Runner->>PG: 写 chunks(status=draft)
    Runner->>PG: document_version.status=chunked

    Worker->>Index: stage=embed create_draft_indexes
    Index->>PG: 创建 index_versions(status=draft)

    Worker->>Index: stage=index write_draft_indexes
    Index->>PG: 写 keyword_index_entries(draft)
    Index->>PG: 写 chunk_index_refs(draft)
    Index->>Model: 批量 embedding
    Index->>Qdrant: upsert draft vector points
    Index->>PG: index_versions.status=ready

    Worker->>Index: stage=publish publish_ready_indexes
    Index->>PG: 校验 chunk 数量、vector ref、权限 payload、维度
    Index->>Qdrant: activate_points
    Index->>PG: 旧 active index -> pending_delete
    Index->>PG: 新 index/document_version/document/chunk/ref/keyword -> active
    Index->>PG: 写索引审计
```

关键状态：

- draft chunk、draft keyword、draft vector point 对查询不可见。
- 只有 `index_versions.status=active`、`documents.lifecycle_status=active`、`documents.index_status=indexed`、`chunks.status=active`、`chunk_index_refs.visibility_state=active` 的组合才允许进入查询。
- publish 前任一校验失败，都不得激活新索引。

## 5. 普通非流式查询链路

```mermaid
sequenceDiagram
    participant Web as 查询前端
    participant API as Query Routes
    participant Query as Query Service
    participant Perm as Permission Service
    participant Rewrite as Query Rewrite
    participant Retrieval as Retrieval Pipeline
    participant PG as PostgreSQL
    participant Qdrant as Qdrant
    participant Model as Model Provider
    participant Context as Context Builder
    participant Answer as Answer Service

    Web->>API: POST /internal/v1/queries
    API->>Query: create_query
    Query->>Perm: build_context
    Perm->>PG: 读取用户、部门、角色、企业权限版本
    Query->>Perm: 解析可查询知识库
    Perm->>PG: 知识库可见性与 access rule 过滤
    Query->>PG: 读取 active index versions
    Query->>Rewrite: 改写/拆分 query
    Query->>Perm: build_filter

    loop 每个 rewritten query
        Query->>PG: keyword_search
        Query->>Qdrant: vector_search
    end

    Query->>Retrieval: Weighted RRF 融合
    Query->>Retrieval: query coverage 候选保留
    Query->>Perm: candidate gate 二次校验
    Query->>Model: rerank
    Query->>Retrieval: quality gate
    Query->>Context: 相邻 chunk 扩展 + MMR + token 预算
    Context->>PG: 读取 chunk 元数据
    Context->>Context: 从对象存储回源完整正文，失败则回落预览
    Query->>Answer: LLM 生成答案
    Answer->>Model: chat completion
    Query->>Query: citation 校验与自动修复
    Query->>PG: 写 query_logs / model_call_logs / diagnostics / audit
    API-->>Web: answer + citations + degraded + confidence
```

降级点：

- 无可访问知识库：返回 `query_scope_empty` 降级。
- 无 active index：返回 `active_index_empty` 降级。
- 向量召回失败：保留关键词召回。
- rerank 失败：使用融合排序。
- LLM 失败：返回可解释降级和引用。
- citation 失败：抑制或修复答案，不直接返回模型原文。

## 6. 流式查询链路

```mermaid
sequenceDiagram
    participant Web as 查询前端
    participant API as Query Stream Routes
    participant Query as Query Service
    participant Answer as Answer Stream Runner
    participant Model as LLM Provider
    participant PG as PostgreSQL

    Web->>API: POST /internal/v1/query-streams
    API->>Query: create_query_stream_plan
    Query-->>API: QueryStreamPlan

    alt plan 无上下文或需要降级
        API-->>Web: SSE 降级事件
    else 可生成答案
        API->>Answer: stream_tokens
        Answer->>Model: stream_complete
        loop provider token
            Model-->>Answer: token delta
            Answer-->>API: 过滤 think/source 后的 token
            API-->>Web: SSE token
        end
        API->>Query: finalize_query_stream
        Query->>PG: 写 query_logs / model_call_logs / diagnostics / audit
        API-->>Web: SSE final 事件
    end
```

关键状态：

- 流式输出期间会过滤 `<think>` 和 `[source:...]` 内部来源占位。
- 最终仍要走 citation 校验、日志写入和审计写入。
- 流式失败时返回结构化 SSE 错误或降级事件。

## 7. 权限变更后的索引刷新链路

```mermaid
sequenceDiagram
    participant Admin as 管理后台
    participant API as Permission/Admin Routes
    participant PermAdmin as Permission Admin Service
    participant PG as PostgreSQL
    participant Worker as Worker
    participant Index as PermissionPayloadRefreshService
    participant Qdrant as Qdrant

    Admin->>API: 修改知识库或文档权限
    API->>PermAdmin: replace permission policy
    PermAdmin->>PG: 校验操作者管理权限
    PermAdmin->>PG: 更新 resource_policies / permission_snapshots / document 或 knowledge_base
    PermAdmin->>PG: enterprise.permission_version + 1
    alt 权限收紧
        PermAdmin->>PG: 写 access_blocks(status=active, reason=permission_tightened)
    end
    PermAdmin->>PG: 创建 import_job(job_type=permission_refresh)
    PermAdmin->>PG: 写权限审计
    API-->>Admin: 返回权限更新结果

    Worker->>PG: claim permission_refresh job
    Worker->>Index: refresh_permission_payloads
    Index->>PG: 读取 active index targets
    Index->>PG: 更新 chunks / keyword_index_entries / chunk_index_refs 权限 payload
    Index->>Qdrant: update_payloads
    Index->>PG: release access_blocks
    Index->>PG: 写 index_permission_payload.refreshed 审计
```

关键状态：

- 权限收紧先写 access block，避免旧索引继续命中。
- payload 刷新完成后才释放 `permission_tightened` access block。
- 查询候选还会二次检查 access block、document/chunk/index 状态和权限版本。
