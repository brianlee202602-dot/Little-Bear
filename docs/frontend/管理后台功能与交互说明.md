# 管理后台功能与交互说明

更新时间：2026-06-03

本文说明 Little Bear 管理后台交付版功能范围、交互方式、权限边界和页面职责。管理后台前端只负责展示和提交请求，权限最终以后端校验为准。

## 访问入口

本地开发默认地址：

```text
http://localhost:5174
```

启动命令：

```bash
make admin
```

管理后台 API 通过 Vite 代理访问后端 `/internal` 和 `/health`。

## 应用结构

管理后台由以下部分组成：

- `AdminRoot`：应用根节点，负责会话、初始化状态、能力加载和全局 provider。
- `AdminShell`：后台布局、导航和当前功能页容器。
- `featureRegistry`：管理后台功能注册表，按权限动态加载功能模块。
- `features/*`：各业务功能模块，模块内拥有自己的页面、composable、modal 和状态。
- `src/api/*`：后端接口访问层。

当前功能注册表包含：

- 配置管理。
- 部门管理。
- 用户管理。
- 知识库管理。
- 查询诊断。

## 登录与初始化

未初始化时，管理后台进入初始化页面，只允许完成 setup 流程。

已初始化后：

- 用户使用账号密码登录。
- 后端返回 JWT。
- 前端加载当前用户、角色和 capabilities。
- 普通员工如果没有管理后台能力，不应进入后台功能页。
- 具备管理能力的用户只看到自己有权限访问的功能菜单。

页面隐藏不是权限控制。用户直接访问接口时，后端仍按 token、scope、部门作用域和知识库作用域校验。

## 配置管理

配置管理用于管理 active config 的版本。

主要功能：

- 查看配置版本列表。
- 查看配置详情。
- 新建配置版本。
- 编辑配置版本。
- 校验配置。
- 激活配置。
- 归档配置。
- 查看配置审计摘要。

交互要求：

- 新建和编辑使用可视化表单，不要求管理员直接写 JSON。
- 激活、归档等高风险操作需要二次确认。
- 列表分页由后端完成。
- 配置详情展示应隐藏 secret value 和内部 hash。

## 部门管理

部门管理用于维护企业组织结构。

主要功能：

- 部门列表。
- 按关键词和状态筛选。
- 新建部门。
- 编辑部门。
- 删除或禁用部门。

交互要求：

- 部门列表显示可读部门名称，不显示不必要的部门编码。
- 查询按钮与输入框、选择器保持同一视觉基线。
- 所有筛选条件传给后端处理。

## 用户管理

用户管理用于维护后台和普通查询用户。

主要功能：

- 用户列表。
- 按关键词、状态和部门筛选。
- 新建用户。
- 编辑用户。
- 重置密码。
- 用户角色绑定。
- 用户部门绑定。

权限边界：

- 系统管理员可管理全企业用户。
- 部门管理员只能创建和管理自己权限范围内的部门用户。
- 角色作用域涉及部门时，默认应选中当前用户所属部门或当前操作上下文部门。
- 后端必须阻止越权创建其他部门用户。

## 知识库管理

知识库管理是文档导入、文档权限、索引和文档运维的主要入口。

主要功能：

- 知识库列表。
- 新建、编辑、删除知识库。
- 设置知识库可见性和默认文档权限。
- 文件夹管理。
- 文档管理弹窗。
- 文档导入。
- 文档权限设置。
- 文档版本、索引版本和 chunk 预览。
- 指定文档或批量文档重建索引。

交互要求：

- 知识库列表中操作项保持一行展示。
- 所属部门显示可读名称。
- 管理者不需要看到知识库 ID、文件夹 ID、文档 ID、版本 ID 等内部标识。
- 点击“文档”后以弹窗展示文档管理，不直接把多层管理内容堆在主列表下。
- “版本与片段”单独弹窗展示，文档版本、索引版本和 chunk 预览分区显示。
- chunk 预览使用列表形式，不展示重复的全文预览块。

## 查询诊断

查询诊断用于排查 RAG 查询、模型调用和索引状态。

主要功能：

- 查询日志列表。
- 查询日志详情弹窗。
- 检索诊断。
- 模型调用日志列表。
- 模型调用日志详情弹窗。
- 索引健康检查。
- Qdrant collection 快照入口。
- collection 重建索引入口。

交互要求：

- 日志列表只显示摘要字段。
- 详情通过弹窗按需加载。
- Trace、request、hash 等内部 ID 不应直接作为主要展示内容，应转换为可读说明或隐藏。
- 降级原因显示简短中文描述。
- 模型调用日志不展示完整 prompt 或文档原文。

## 列表和分页规范

后台列表必须使用后端分页：

- `page`
- `page_size`
- `total`

后台列表必须把业务筛选条件传给后端：

- `keyword`
- `status`
- `department_id`
- `kb_id`
- `date_range`

前端不得拉取全部数据后自行分页或权限过滤。

## 弹窗规范

当前后台大量编辑和详情操作使用弹窗。

通用要求：

- 弹窗打开时按需加载详情。
- 关闭弹窗不应破坏主列表筛选状态。
- 高风险操作使用确认控件。
- 表单保存后刷新当前列表或局部详情。
- 弹窗中的滚动区域应避免和外层页面滚动条重叠。

## 错误展示

前端应展示后端结构化错误：

- `error_code`
- `message`
- `request_id`
- `stage`
- `retryable`

不应吞掉错误或只显示“请求失败”。对于安全相关错误，不应把内部细节、secret、完整 token、完整 prompt 或文档原文展示给用户。

## 交付边界

- 管理后台前端负责能力菜单和交互体验，不能替代后端权限控制。
- 配置审计、查询日志和模型调用日志以后台页面查看为主，不包含独立告警控制台。
- Redis 业务缓存不属于交付版运行闭环，后台不提供缓存管理页面。
