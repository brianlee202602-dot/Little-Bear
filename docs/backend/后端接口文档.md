# Little Bear 后端接口文档

更新时间：2026-06-02

本文按当前 `apps/api/app/api/routes` 的实际实现整理后端接口用途。请求体、响应体、字段类型、HTTP 状态码和示例由 FastAPI 自动文档呈现，开发时以 `/docs`、`/redoc` 和 OpenAPI 输出为准；本文只补充接口作用、调用场景、关键参数含义、权限边界和确认头语义。

## 通用约定

- 所有业务接口统一位于 `/internal/v1` 下，健康检查位于 `/health/*`。
- 除 setup 和登录接口外，调用方应使用 `Authorization: Bearer <access_token>`。
- `POST /internal/v1/token-refreshes` 使用 refresh token，其余受保护业务接口使用 access token。
- 列表接口统一使用后端分页：`page` 表示页码，`page_size` 表示每页数量，响应包含 `pagination.total`。
- 常见筛选参数：
  - `keyword`：按名称、标题、用户名等文本字段过滤。
  - `status`：按业务状态过滤。
  - `kb_id`：按知识库过滤。
  - `stage`：按导入任务阶段过滤。
  - `job_type`：按导入或索引任务类型过滤。
- 高风险写操作要求确认头，不满足时返回确认缺失错误：
  - `x-setup-confirm: initialize`
  - `x-user-confirm`
  - `x-department-confirm`
  - `x-knowledge-base-confirm`
  - `x-folder-confirm`
  - `x-document-confirm`
  - `x-role-binding-confirm`
  - `x-config-confirm`
  - `x-index-confirm`
  - `x-permission-confirm`
- `request_id` 用于一次 HTTP 请求排查；查询链路还会生成 `trace_id`，但面向普通用户前端通常只展示脱敏后的 debug id。
- 系统未初始化时，普通业务接口会被 setup guard 拦截，只开放 setup 和健康检查相关入口。

## 健康检查

| 方法 | 路径 | 作用 | 关键说明 |
|---|---|---|---|
| GET | `/health/live` | 进程存活检查 | 用于容器存活探针，只确认 API 进程可响应。 |
| GET | `/health/ready` | 服务就绪检查 | 用于发布和负载均衡就绪判断，会反映初始化、active config 和关键 bootstrap 状态。 |

## Setup 初始化接口

这些接口只用于空库或恢复初始化阶段。setup token 只能访问 setup 校验和初始化，不能访问普通业务接口。

| 方法 | 路径 | 作用 | 关键参数 / 头 | 权限 |
|---|---|---|---|---|
| GET | `/internal/v1/setup-state` | 查询当前系统初始化状态 | 无需业务 token。用于前端判断是否进入初始化页。 | 无 |
| POST | `/internal/v1/setup-config-validations` | 校验初始化 payload | `Authorization` 使用 setup token；请求体是完整初始化配置。只校验和写审计，不激活配置。 | `setup:validate` |
| PUT | `/internal/v1/setup-initialization` | 执行初始化 | `x-setup-confirm=initialize`；初始化成功后 setup token 会被消费。 | `setup:initialize` |

## 管理后台：用户管理

用户管理接口由管理后台调用。后端会按当前操作者的角色、部门和 scope 做权限过滤，前端隐藏菜单不构成权限控制。

| 方法 | 路径 | 作用 | 关键参数 / 头 | 权限 |
|---|---|---|---|---|
| GET | `/internal/v1/admin/users` | 分页查询用户列表 | `keyword` 按登录名或显示名过滤；`status` 按账号状态过滤。 | `user:read` |
| POST | `/internal/v1/admin/users` | 创建用户 | `x-user-confirm=create-admin` 用于确认创建高风险管理员账号。部门管理员只能创建权限允许范围内的用户。 | `user:manage` |
| GET | `/internal/v1/admin/users/{user_id}` | 查询用户详情 | `user_id` 是目标用户 ID。 | `user:read` |
| PATCH | `/internal/v1/admin/users/{user_id}` | 修改用户基础信息和状态 | `x-user-confirm=disable-admin` 用于确认禁用管理员账号。 | `user:manage` |
| DELETE | `/internal/v1/admin/users/{user_id}` | 删除或停用用户 | `x-user-confirm=delete`。 | `user:manage` |
| GET | `/internal/v1/admin/users/{user_id}/departments` | 查询用户所属部门 | 用于部门绑定弹窗。 | `org:read` |
| PUT | `/internal/v1/admin/users/{user_id}/departments` | 替换用户部门绑定 | `x-department-confirm=replace-primary` 用于确认替换主部门。 | `org:manage` |
| PUT | `/internal/v1/admin/users/{user_id}/password` | 管理员重置用户密码 | `x-user-confirm=reset-password`。 | `user:manage` |
| DELETE | `/internal/v1/admin/users/{user_id}/lock` | 解锁用户账号 | 用于登录失败锁定后的恢复。 | `user:manage` |

| POST | `/internal/v1/admin/documents/{doc_id}/index-jobs` | 为单个文档创建重建索引任务 | `x-index-confirm=rebuild`。 | `document:index` |
| GET | `/internal/v1/admin/index-health` | 查询 collection 健康状态 | 对比 Qdrant 与数据库索引版本、ref 状态。 | `document:index` |
| GET | `/internal/v1/admin/index-collections/{collection_name}/snapshots` | 查询 Qdrant collection 快照 | `collection_name` 是 Qdrant collection 名称。 | `document:index` |
| POST | `/internal/v1/admin/index-collections/{collection_name}/snapshots` | 创建 Qdrant 快照 | `x-index-confirm=snapshot`。 | `document:index` |
| PUT | `/internal/v1/admin/index-collections/{collection_name}/snapshot-recoveries` | 从快照恢复 collection | `x-index-confirm=restore`；会覆盖当前 collection 数据。 | `document:index` |

## 导入与任务接口

导入接口只创建任务，真正解析、切块、embedding 和索引写入由 Worker 执行。上传后如果 Worker 未启动，任务会停留在 queued。

| 方法 | 路径 | 作用 | 关键参数 / 头 | 权限 |
|---|---|---|---|---|
| POST | `/internal/v1/knowledge-bases/{kb_id}/documents` | 上传文件并创建导入任务 | `multipart/form-data`；`files` 是文件列表；`owner_department_id`、`visibility`、`folder_id` 指定文档默认权限和目录；`idempotency_key` 防重复提交。 | `document:import` |
| POST | `/internal/v1/knowledge-bases/{kb_id}/document-imports` | 创建 URL 或 metadata batch 导入任务 | `idempotency_key` 可放请求体或 header。 | `document:import` |
| GET | `/internal/v1/import-jobs/{job_id}` | 查询当前用户自己的导入任务详情 | 只能看自己的任务。 | `import_job:read:self` |
| PATCH | `/internal/v1/import-jobs/{job_id}` | 取消当前用户自己的导入任务 | 当前只支持把状态改为 `cancelled`。 | `import_job:manage:self` |
| POST | `/internal/v1/import-jobs/{job_id}/retries` | 重试当前用户自己的导入任务 | 用于失败任务恢复。 | `import_job:manage:self` |
| GET | `/internal/v1/admin/import-jobs` | 管理端分页查询导入 / 索引任务 | `status`、`stage`、`kb_id`、`job_type` 过滤。 | `import_job:read` |
| POST | `/internal/v1/admin/index-jobs/retries` | 管理端批量重试索引任务 | `x-index-confirm=retry`。 | `document:index` |
| GET | `/internal/v1/admin/import-jobs/{job_id}` | 管理端查询任意导入任务详情 | 受企业和管理权限过滤。 | `import_job:read` |

## 权限策略接口

权限策略接口属于管理端写操作。当前知识库权限和文档权限修改统一由 `modules.permissions.PermissionAdminService` 处理。

| 方法 | 路径 | 作用 | 关键参数 / 头 | 权限 |
|---|---|---|---|---|
| PUT | `/internal/v1/knowledge-bases/{kb_id}/permissions` | 替换知识库可见性、默认文档权限和 ACL 规则 | `x-permission-confirm=replace`；会校验默认文档权限必须落在知识库可访问范围内。 | `permission:manage` |
| PUT | `/internal/v1/documents/{doc_id}/permissions` | 替换文档可见性和归属部门 | `x-permission-confirm=replace`；权限收紧后会触发刷新 / 阻断链路。 | `permission:manage` |

## 查询与会话接口

查询接口会创建或更新服务端会话消息。RAG 检索当前只基于本轮问题执行，不把历史对话拼入检索 query；历史消息用于前端展示和后续扩展。

| 方法 | 路径 | 作用 | 关键参数 | 权限 |
|---|---|---|---|---|
| GET | `/internal/v1/query-conversations` | 查询当前用户历史查询会话 | 分页返回会话摘要。 | `rag:query` |
| POST | `/internal/v1/query-conversations` | 主动创建空会话 | 可传标题和默认知识库列表。 | `rag:query` |
| GET | `/internal/v1/query-conversations/{conversation_id}` | 查询会话详情和消息列表 | `page`、`page_size` 控制消息分页。 | `rag:query` |
| DELETE | `/internal/v1/query-conversations/{conversation_id}` | 删除当前用户自己的会话 | 软删除，不影响已写 query log。 | `rag:query` |
| POST | `/internal/v1/queries` | 非流式 RAG 查询 | 请求体包含 `query`、`kb_ids`、`mode`、`filters`、`top_k`、`include_sources`、可选 `conversation_id`。 | `rag:query` |
| POST | `/internal/v1/query-streams` | SSE 流式 RAG 查询 | 与非流式请求体一致；返回 `metadata`、`token`、`citation`、`done` 等 SSE 事件。 | `rag:query` |

## 审计与诊断日志

审计接口只读，不读取 Secret Store，不返回完整 prompt、文档原文或未脱敏敏感字段。

| 方法 | 路径 | 作用 | 关键参数 | 权限 |
|---|---|---|---|---|
| GET | `/internal/v1/admin/audit-logs` | 查询审计日志列表 | `actor_id`、`action`、`resource_type`、`result`、`risk_level` 过滤。 | `audit:read` |
| GET | `/internal/v1/admin/audit-logs/{audit_id}` | 查询审计日志详情 | 返回脱敏 summary。 | `audit:read` |
| GET | `/internal/v1/admin/query-logs` | 查询问答日志列表 | `user_id`、`kb_id`、`status`、`degraded`、`degrade_reason`、`request_id`、`trace_id`、`error_code` 过滤。 | `audit:read` |
| GET | `/internal/v1/admin/query-logs/{query_log_id}` | 查询问答日志详情 | 用于管理后台查询诊断弹窗。 | `audit:read` |
| GET | `/internal/v1/admin/model-call-logs` | 查询模型调用日志列表 | `model`、`model_type`、`caller`、`status`、`degraded`、`request_id`、`trace_id`、`error_code` 过滤。 | `audit:read` |
| GET | `/internal/v1/admin/model-call-logs/{model_call_log_id}` | 查询模型调用日志详情 | 展示模型路由、调用方、耗时、token 摘要、hash 和错误码，不展示完整 prompt 或文档原文。 | `audit:read` |

## 接口使用建议

- 前端不要自行做权限过滤；列表、详情、查询和来源接口都会在后端重新鉴权。
- 管理后台列表页应使用后端分页和筛选，不拉取全部数据后前端过滤。
- 删除、权限扩大、索引重建、快照恢复、配置发布等高风险操作必须携带对应确认头。
- 查询接口返回降级结果时，前端应显示降级状态和简短原因，不应把无引用答案伪装成正常答案。
- 普通用户点击 citation 时应调用来源接口验证来源，不要直接信任模型回答中的 source 标记文本。
