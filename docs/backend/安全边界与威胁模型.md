# 安全边界与威胁模型

更新时间：2026-06-03

本文说明 Little Bear 交付版安全边界、主要威胁和已有控制措施。本文面向开发和审查，不替代组织级安全制度。

## 保护对象

系统需要保护的核心对象：

- 用户身份和 JWT。
- 密码哈希。
- Secret Store 中的密钥。
- 企业、部门、用户和角色关系。
- 知识库、文档、chunk、文档版本、索引版本。
- MinIO 中的原始文件和 chunk 正文。
- Qdrant 中的向量和权限 payload。
- 查询日志、模型调用日志和审计日志。
- active config。

## 信任边界

### 前端到后端

前端不可信。前端隐藏菜单、隐藏按钮、禁用输入框都不构成权限控制。

后端必须重新校验：

- JWT。
- scope。
- 部门作用域。
- 知识库作用域。
- 文档可见性。
- 高风险操作确认 header。

### API 到外部 provider

模型 provider、Qdrant、MinIO、Redis 都是外部依赖。它们不可用或响应异常时，业务链路必须按错误和降级规则处理。

禁止把外部 provider 响应直接当作可信业务事实。

### PostgreSQL 到派生状态

PostgreSQL 是业务事实源。Qdrant、Redis、关键词索引、对象存储中的派生内容必须与 PostgreSQL 状态校验。

查询候选进入上下文前不能只相信 Qdrant payload。

## 身份认证边界

交付版控制：

- 本地账号密码登录。
- 密码使用 argon2 哈希。
- JWT 使用 PyJWT。
- access / refresh token 分工。
- setup JWT 只能访问 setup 相关接口。

主要威胁：

- 伪造或篡改 token。
- refresh token 调用普通业务 API。
- 过期 token 访问接口。
- 普通员工访问管理后台。

控制措施：

- 后端校验 token 类型、过期时间和 scope。
- 管理接口要求管理 scope。
- setup guard 阻断初始化状态不合法的业务访问。
- 前端登录后加载 capabilities，但最终以后端权限为准。

## 权限和数据隔离边界

当前权限由 RBAC、部门作用域、知识库作用域、知识库可见性和文档可见性共同构成。

查询候选必须满足：

- 权限过滤条件下推到向量和关键词召回。
- 文档生命周期为 active。
- 文档索引状态为 indexed。
- chunk 状态为 active。
- index version 状态为 active。
- chunk index ref 为 active。
- 不存在有效 access block。
- source / citation 读取时重新鉴权。

主要威胁：

- 跨部门读取文档。
- 知识库列表可见导致文档泄露。
- 权限收紧后旧索引继续可见。
- deleted / blocked / draft / archived 内容被检索。
- source 详情接口越权。

控制措施：

- Permission Service 统一构建权限上下文。
- access block 阻断旧权限或删除后的可见性。
- candidate gate 做权限和状态二次过滤。
- citation validator 拦截 unauthorized citation。
- 详情接口重新鉴权，不继承列表可见性。

## 导入和索引边界

导入链路从 API 创建任务，Worker 执行后台阶段。

主要威胁：

- 未授权用户为其他部门导入文档。
- draft vector 被查询命中。
- Qdrant 写入失败但 PostgreSQL 发布 active。
- Worker 重复执行导致状态错乱。
- 文件解析结果或 chunk 正文丢失后仍生成错误答案。

控制措施：

- 导入 API 校验 owner department 和知识库管理权限。
- Worker 使用锁和幂等阶段。
- draft index 发布前对查询不可见。
- 发布前校验数量、维度、payload、权限快照和 index version。
- Qdrant 或关键词索引失败时不得发布 active index。
- Context Builder 可从对象存储回源读取完整 chunk 正文，失败时降级 preview。

## 模型调用边界

模型 provider 输出不可信。

主要威胁：

- LLM 生成不存在的引用。
- LLM 生成未被资料支撑的答案。
- provider 返回恶意或格式异常响应。
- prompt 或文档原文泄露到日志。
- provider 密钥泄露。

控制措施：

- AnswerService 后执行 citation 校验。
- citation invalid / unauthorized 时抑制原答案或结构化降级。
- 模型调用日志只记录 hash、摘要、耗时、错误码。
- Secret Store 管理 provider 密钥。
- provider HTTP 错误和响应异常统一转换为模型错误码。

## 配置和 Secret 边界

active config 是业务运行配置事实。

主要威胁：

- 通过 `.env` 绕过业务配置。
- 发布不可用配置导致服务错误。
- secret value 泄露。
- 历史配置被误激活。

控制措施：

- 业务配置必须通过 active config。
- 配置发布先 schema 校验再依赖校验。
- 发布失败时 active pointer 不切换。
- Secret value 加密存储，响应和日志不展示。
- 归档配置避免误激活。

## 日志和审计边界

日志和审计用于诊断，但不能成为数据泄露通道。

主要威胁：

- 查询日志泄露完整 prompt。
- 模型调用日志泄露文档原文。
- 审计日志泄露 token 或 secret。
- 前端直接展示内部 trace/hash。

控制措施：

- 日志记录 request_id / trace_id / hash / 摘要。
- 管理后台列表只展示摘要字段。
- 详情按权限读取。
- 前端不展示完整 token、secret、prompt、文档原文。

## 威胁矩阵

| 威胁 | 当前控制措施 | 剩余风险 |
| --- | --- | --- |
| 普通用户调用管理接口 | JWT scope 和后端权限校验 | 需要持续回归测试覆盖新增接口 |
| 跨部门文档查询 | PermissionFilter、candidate gate、citation 校验 | 旧索引和缓存必须持续 fail closed |
| draft index 命中 | index version 和 ref 状态过滤 | 新增索引入口必须遵守发布流程 |
| LLM 编造引用 | citation validator | 需要持续优化自动修复和降级体验 |
| Provider 密钥泄露 | Secret Store 和日志脱敏 | master key 管理依赖部署环境 |
| 配置误发布 | schema + dependency validation + confirm header | 依赖健康检查不能覆盖所有语义错误 |
| Qdrant 状态漂移 | index health 和重建索引 | 恢复后需要人工或自动运维校验 |
| 日志敏感信息泄露 | 摘要和 hash 记录 | 新增日志字段需逐项审查 |

## 必须保持的安全回归

- 未初始化时访问普通业务 API。
- setup JWT 越权访问普通业务 API。
- refresh token 调用普通业务 API。
- 普通员工调用管理员接口。
- 跨部门查询文档。
- 权限收紧后旧索引不可见。
- deleted / blocked / draft / archived 内容不可见。
- source 读取重新鉴权。
- citation unauthorized 抑制答案。
- 模型调用日志不展示完整 prompt 或文档原文。

## 交付边界

- 仓库不提供 Kubernetes / Helm 级生产安全配置。
- TLS、WAF、堡垒机、云 IAM 等部署侧安全能力需要由部署环境提供。
- Redis 业务缓存不属于交付版运行闭环；最终答案缓存如启用，必须加入权限 hash、配置版本、active index 版本和 citation 轻量校验。
