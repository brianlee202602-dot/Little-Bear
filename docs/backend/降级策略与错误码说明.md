# 降级策略与错误码说明

更新时间：2026-06-03

本文说明 Little Bear 当前查询链路、引用校验和业务接口的降级与错误处理方式。本文不重复 FastAPI 自动文档可展示的字段定义，只解释错误和降级背后的业务含义。

## 1. 降级与 fail closed 的区别

当前系统将异常处理分为两类。

降级：

- 系统仍能返回一个受控响应。
- 响应会明确说明没有生成完整可信答案的原因。
- 不返回未经校验的模型原文。
- 写入 query log、model call log、audit 或检索诊断。

fail closed：

- 系统拒绝继续执行或拒绝返回敏感内容。
- 典型场景是未授权、权限越界、bootstrap 不可用、数据状态不可见、导入索引发布失败。
- 不通过前端隐藏菜单替代后端权限判断。

RAG 查询中，多数模型和检索异常会进入“可解释降级”；权限和引用越权必须 fail closed，不允许把原始答案透传给用户。

## 2. 统一错误响应结构

后端结构化错误由 `apps/api/app/api/errors.py` 生成，主要字段包括：

- `request_id`：本次请求 ID。
- `error_code`：错误码。
- `message`：面向调用方的错误说明。
- `stage`：错误发生阶段。
- `retryable`：是否建议重试。
- `details`：必要的结构化详情。

setup guard 也返回相同结构，并在响应头中写入 `x-request-id` 和 `x-trace-id`。

## 3. 查询降级响应

查询降级答案由 `apps/api/app/modules/query/degrade_policy.py` 生成。该实现保证即使内部发生检索、上下文、模型或引用问题，用户也会收到一个解释性回答。

降级回答通常包含：

- 本次问题没有得到可直接采信答案的说明。
- 系统找到多少条当前账号可访问的引用资料。
- 没有答案的核心原因。
- 用户可以继续查看引用资料或换一种更具体问题重新查询的提示。

## 4. 主要降级场景

### 4.1 embedding 失败

可能原因：

- embedding provider 不可用。
- embedding provider HTTP 错误。
- embedding 运行时配置不可用。
- query embedding 生成失败。
- 向量检索不可用。

当前处理：

- 尝试使用关键词检索或已有召回路径继续处理。
- 如果最终没有可用上下文，则返回降级答案。
- 典型原因码包括 `vector_runtime_config_unavailable`、`query_embedding_unavailable`、`vector_retriever_unavailable`、`vector_search_failed`。

### 4.2 rerank 不可用

可能原因：

- rerank provider 不可用。
- rerank provider HTTP 错误。
- rerank 返回数量与输入不一致。
- rerank 超时。

当前处理：

- 不直接中断查询。
- 使用融合分数或召回排序继续构建候选。
- 写入模型调用日志或查询日志中的降级信息。
- 典型原因码包括 `RERANK_PROVIDER_UNAVAILABLE`、`RERANK_PROVIDER_HTTP_ERROR`、`RERANK_INPUT_MISMATCH`。

### 4.3 LLM 超时或 HTTP 错误

可能原因：

- LLM provider 超时。
- LLM provider HTTP 错误。
- LLM 配置不可用。
- 流式响应未返回有效结果。

当前处理：

- 不伪造答案。
- 返回已检索到的授权引用和解释性降级答案。
- 典型原因码包括 `LLM_PROVIDER_HTTP_ERROR`、`llm_runtime_config_unavailable`、`llm_stream_result_missing`。

### 4.4 citation invalid

当前 citation 校验识别模型输出中的：

```text
[source:<uuid>]
```

如果模型输出了格式错误的引用占位符，会触发 `citation_invalid_format`。

当前处理：

- 如果系统可以从已授权候选中安全附加引用，会执行 citation 自动修复。
- 如果无法修复，则抑制模型原答案，返回降级说明。

### 4.5 citation unauthorized

如果模型输出的 source id 不在本次允许引用集合中，会触发 `citation_unauthorized`。

当前处理：

- 必须 fail closed。
- 不返回模型原答案。
- 返回解释性降级答案。
- 保留授权引用资料供用户查看。

这是权限安全场景，不属于普通可忽略降级。

### 4.6 文档为空或上下文为空

可能原因：

- 文档导入后没有生成 active chunk。
- 文档被删除、被 block 或索引未发布。
- 召回结果经过权限过滤后为空。
- 候选经过质量 gate 后为空。

当前处理：

- 返回降级答案。
- 典型原因码包括 `llm_context_empty`、`query_scope_empty`。

### 4.7 权限过滤后无可用片段

当前查询候选进入上下文前必须经过权限过滤和状态过滤。以下内容不得进入上下文：

- 用户无权访问的知识库或文档。
- deleted / blocked 文档。
- draft index。
- archived index。
- inactive chunk。
- access block 命中的内容。

如果过滤后无可用片段，系统返回降级答案，不扩大用户权限范围。

### 4.8 低相关候选被拦截

当前候选质量 gate 会拦截相关性不足的候选，典型原因码包括：

- `retrieval_relevance_too_low`
- `retrieval_quality_too_low`

处理方式：

- 不把低质量候选提交给 LLM 生成貌似合理但无依据的答案。
- 返回降级说明，告知没有找到足够相关的资料。

## 5. 允许返回降级答案的场景

以下场景允许返回降级答案：

- embedding 或向量检索不可用，但系统可以解释检索失败或使用关键词检索补偿。
- rerank 不可用，但候选可以按融合分数继续排序。
- LLM 不可用，但存在授权引用可展示。
- 找到候选但候选质量不足。
- 找到候选但没有形成可用 LLM 上下文。
- citation 缺失或格式错误，且无法安全修复。
- 文档为空、未索引或权限过滤后无可用片段。

## 6. 必须 fail closed 的场景

以下场景不得返回敏感内容或未经校验答案：

- 未登录、token 过期、scope 不足。
- 普通用户访问管理员接口。
- setup 未完成或 ServiceBootstrap 不可用。
- 知识库、文档、source 详情越权访问。
- 模型生成了未授权 citation。
- 文档已删除、被 access block 或索引处于 draft 状态。
- 导入索引发布失败。
- 权限收紧后的旧索引或旧缓存仍可能命中。
- Secret、token、密码、完整 prompt 或文档原文可能泄露。

## 7. 常见错误码含义

| 错误码或原因码 | 含义 | 当前处理 |
| --- | --- | --- |
| `SERVICE_BOOTSTRAP_UNAVAILABLE` | active config 或关键依赖未准备好 | 业务 API 拒绝服务 |
| `SETUP_REQUIRED` | 系统尚未初始化 | 只允许 setup 相关接口 |
| `SETUP_MIGRATION_REQUIRED` | 数据库迁移未达到当前要求 | 拒绝业务 API |
| `LLM_PROVIDER_HTTP_ERROR` | LLM provider HTTP 调用失败 | 降级，不透传未校验答案 |
| `RERANK_PROVIDER_UNAVAILABLE` | rerank provider 不可用 | 使用融合分数或降级 |
| `citation_missing` | 模型答案缺少引用 | 视是否可修复决定自动附加或降级 |
| `citation_invalid_format` | 引用占位符格式无效 | 可修复则附加授权引用，否则降级 |
| `citation_unauthorized` | 模型引用了未授权来源 | fail closed，抑制原答案 |
| `llm_context_empty` | 没有可提交给 LLM 的上下文 | 降级 |
| `query_scope_empty` | 当前用户没有可查询知识库范围 | 降级 |
| `retrieval_relevance_too_low` | 最高相关性不足 | 降级 |
| `retrieval_quality_too_low` | 召回整体质量不足 | 降级 |

## 8. 排障建议

查询返回降级时，优先按以下顺序排查：

1. 查看 query log 中的 `degrade_reason`、候选数量和引用数量。
2. 查看 query retrieval diagnostics，确认 query rewrite、关键词召回、向量召回、融合、rerank 和质量 gate 各阶段输出。
3. 查看 model call logs，确认 embedding、rerank、LLM 是否有 HTTP 错误、超时或认证错误。
4. 查看 index health，确认 collection、active refs、向量维度和 pending delete 是否正常。
5. 查看权限和 access block，确认文档是否被删除、被阻断或用户无权访问。

## 9. 交付边界

- 降级策略会给用户解释“为什么没有可信答案”，但不会自动发起二次追问。
- 低相关候选被拦截后不会让 LLM 自由发挥。
- citation 自动修复只基于当前已授权候选，不会扩大引用范围。
- 最终答案缓存不属于交付版运行链路，因此降级结果不会进入答案缓存。
