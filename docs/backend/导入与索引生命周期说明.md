# 导入与索引生命周期说明

更新时间：2026-06-03

本文说明文档从上传到可查询的完整生命周期，以及 Worker、对象存储、索引账本、Qdrant 和权限刷新之间的关系。

## 1. 生命周期总览

```text
上传请求
-> API 校验权限、大小、文件类型、幂等键
-> 创建 document / document_version / import_job
-> 原始文件写入对象存储
-> Worker claim
-> validate
-> parse
-> clean
-> chunk
-> embed
-> index
-> publish
-> cleanup
-> finished / success
```

上传接口返回 queued job 只代表导入任务已创建，不代表文档已经可查询。

## 2. Import Job 创建

API 通过 `ImportService.create_document_import` 创建导入任务。

创建阶段会做：

- 文件名、content type、大小和类型校验。
- actor 是否可导入目标知识库和目标 owner department 校验。
- 幂等键校验。
- 原始文件写入对象存储。
- 创建 `documents`。
- 创建 `document_versions`。
- 创建 `import_jobs`。
- 写导入审计。

### 2.1 初始文档状态

新导入文档在 publish 前通常处于：

- `documents.lifecycle_status=draft`
- `documents.index_status=none` 或 `indexing`
- `document_versions.status=draft`
- `chunks.status=draft`

这些状态都不可查询。

## 3. Worker Claim 与锁

Worker 主循环通过 `ImportWorkerService.claim_next_job` 领取任务。

领取条件：

- `status in ('queued', 'retrying')` 且到达 `next_retry_at`。
- 或 `status=running` 但锁已过期。
- `locked_until IS NULL OR locked_until < now()`。

领取时使用：

- `FOR UPDATE SKIP LOCKED`
- `locked_by`
- `locked_until`
- `attempt_count + 1`

这保证多个 Worker 并发时不会重复领取同一任务。

## 4. 阶段推进

Worker 对 running job 调用 `advance_claimed_job`。每次推进前会校验：

- 当前 Worker 持有锁。
- `locked_until > now()`。
- job 仍为 `running`。

如果任务被请求取消，会进入取消流程。

## 5. Validate 阶段

`validate` 阶段将目标文档标记为 indexing：

- `documents.index_status=indexing`

如果任务不包含 document ids，会失败并写入错误。

## 6. Parse 阶段

`parse` 阶段读取原始对象并解析为结构化文本。

当前解析器支持：

- TXT / Markdown。
- PDF。
- DOCX。

输出：

- parsed text。
- parsed blocks。
- parser_version。
- parsed_object_key。

状态变化：

- `document_versions.status=parsed`
- `document_versions.parsed_object_key` 写入对象 key。

解析失败会根据错误是否 retryable 决定重试或失败。

## 7. Clean 阶段

`clean` 阶段清洗 parsed 文本：

- 去除控制字符。
- 规范空白和换行。
- 保留或补齐 parsed blocks。

输出：

- cleaned text。
- cleaned blocks。
- cleaner_version。
- cleaned_object_key。

`cleaned_object_key` 写入对象存储，供后续 chunk 阶段读取。

## 8. Chunk 阶段

当前使用 `StructureAwareChunker`。

切块策略：

- 基于 heading、paragraph、list_item、table、code、page_break 等 block。
- 优先按标题和句段组织，不是固定长度硬切。
- 对超长文本按句子边界拆分。
- 为 chunk 写入 heading_path、page_start、page_end、source_offsets。
- 每个 chunk 完整正文写入对象存储。

数据库写入：

- `chunks.text_object_key`
- `chunks.text_preview`
- `chunks.heading_path`
- `chunks.source_offsets`
- `chunks.page_start`
- `chunks.page_end`
- `chunks.content_hash`
- `chunks.token_count`
- `chunks.status=draft`
- `chunks.permission_snapshot_id`

状态变化：

- `document_versions.status=chunked`
- `document_versions.chunker_version` 更新。

## 9. Embed 阶段：创建 Draft Index Version

`embed` 阶段调用 `IndexingService.create_draft_indexes`。

该阶段会：

- 读取目标 document_version。
- 统计 draft chunks。
- 校验必须存在 chunk。
- 创建 `index_versions(status=draft)`。
- 写入 embedding_model、model_version、dimension、collection_name。
- 写入 permission_snapshot_hash 和 payload_hash。
- 写索引创建审计。

如果目标已有 draft / ready / active index，普通导入会复用现有版本；重建索引请求可强制创建新版本。

## 10. Index 阶段：写 Draft Keyword 与 Vector

`index` 阶段调用 `IndexingService.write_draft_indexes`。

该阶段会：

1. 读取 draft chunks。
2. 插入 `keyword_index_entries(visibility_state=draft)`。
3. 插入 `chunk_index_refs(visibility_state=draft)`。
4. 生成 draft vector points。
5. 调用 Qdrant 写入 draft vector points。
6. 当 chunk ref 数量匹配 index version chunk_count 时，将 `index_versions.status` 改为 `ready`。

如果 Qdrant 或 embedding 写入失败，错误码通常表现为：

- `INDEX_VECTOR_WRITE_FAILED`

此时 index version 不会发布为 active。

## 11. Publish 阶段：激活索引

`publish` 阶段调用 `IndexPublishService.publish_ready_indexes`。

发布前校验：

- ready index version 必须存在。
- 当前 chunk 数必须等于 index version chunk_count。
- draft chunk 数必须匹配。
- draft vector ref 数必须匹配。
- embedding dimension 必须等于 active config dimension。
- keyword payload 必须包含 owner_department、visibility 等权限字段。
- index permission snapshot hash 必须与当前文档权限快照匹配。

发布动作：

- Qdrant draft point 激活。
- 旧 active index version 改为 `pending_delete`。
- 新 index version 改为 `active`。
- 旧 active document version 改为 `archived`。
- 新 document version 改为 `active`。
- document 改为 `lifecycle_status=active`、`index_status=indexed`。
- draft chunks 改为 `active`。
- chunk index refs 改为 `active`。
- keyword entries 改为 `active`。
- 写 `index_version.activated` 审计。

## 12. Cleanup 阶段

`cleanup` 阶段用于清理 pending_delete 索引。清理失败不应影响已经发布的 active index，但需要记录错误并可重试。

## 13. 失败、重试与锁接管

Worker 阶段发生 `ImportServiceError` 时：

1. 读取当前 claimed job。
2. 根据 `retryable` 和 `attempt_count < max_attempts` 判断是否重试。
3. 可重试则写：
   - `status=retrying`
   - `next_retry_at`
   - `locked_by=NULL`
   - `locked_until=NULL`
4. 不可重试或超过次数则写：
   - `status=failed`
   - `finished_at=now()`
5. 错误摘要写入 `result_json.last_error`。
6. 写入 worker 审计。

如果 Worker 崩溃，锁到期后其他 Worker 可重新领取 running job。

## 14. Draft 与 Active 的区别

| 对象 | Draft / Ready | Active |
| --- | --- | --- |
| `chunks` | `status=draft`，不可查询 | `status=active`，可作为候选 |
| `index_versions` | `draft` / `ready`，不可查询 | `active`，查询只加载 active |
| `keyword_index_entries` | `visibility_state=draft`，不可查询 | `visibility_state=active` |
| `chunk_index_refs` | `visibility_state=draft`，不可查询 | `visibility_state=active` |
| Qdrant points | draft payload，不应被查询命中 | active payload，可被召回 |

查询链路不会读取 draft / ready index。上传后必须等 publish 完成，文档才可查询。

## 15. 权限变更后的 Payload 刷新

权限变更会创建 `permission_refresh` import job。

Worker 在 `index` 阶段执行：

- `PermissionPayloadRefreshService.refresh_permission_payloads`

刷新动作：

- 读取 active index targets。
- 更新 chunks 的 permission_snapshot_id。
- 更新 `keyword_index_entries.owner_department_id`。
- 更新 `keyword_index_entries.visibility`。
- 更新 `keyword_index_entries.indexed_permission_version`。
- 更新 `chunk_index_refs.visibility_state` 和 `indexed_permission_version`。
- 调用 Qdrant `update_payloads`。
- 释放 reason 为 `permission_tightened` 的 active access block。
- 写 `index_permission_payload.refreshed` 审计。

权限收紧时 access block 会先阻断查询，payload 刷新完成后再释放。

## 16. 文档删除后的阻断

文档删除或知识库删除必须先让查询 fail closed：

- 更新业务状态或软删除字段。
- 写 active access block。
- 异步执行索引删除或 payload 刷新任务。

即使外部索引未立即清理，查询候选仍会因为状态或 access block 被拒绝。

## 17. 为什么上传后不会立刻可查询

上传只是创建导入任务。文档要可查询，必须满足：

- Worker 已完成 parse、clean、chunk。
- embedding 和 Qdrant draft 写入成功。
- keyword/ref 账本完整。
- publish 前校验通过。
- index/document/chunk/ref/keyword 全部进入 active 状态。

任何阶段失败都会阻止文档进入查询上下文。
