# 后端模块职责索引

更新时间：2026-06-03

本文按交付版代码结构说明后端模块职责、入口和边界。后端采用模块化单体 + Worker，不是微服务拆分。

## 顶层结构

```text
apps/api/app/api          HTTP route、依赖、schema、presenter
apps/api/app/modules      业务领域模块
apps/api/app/adapters     外部系统 adapter
apps/api/app/db           数据库连接、ORM metadata、迁移运行依赖
apps/api/app/shared       无业务归属的公共能力
apps/worker               导入与索引后台进程入口
```

依赖方向：

```text
api/routes -> api/dependencies / api/presenters / api/schemas
api/routes -> modules/<domain> service/facade
modules/<domain> -> repository / policy / runtime / shared / db
runtime -> config / secrets / adapters
adapters -> 外部系统
```

禁止：

- `modules` 依赖 `api/routes`。
- `shared` 依赖业务模块。
- route 层直接访问 Qdrant、MinIO、模型 provider。
- Worker 调用 FastAPI route function。

## API 层

### `api/routes`

职责：

- HTTP 入参解析。
- 鉴权依赖。
- 分页参数。
- 调用 service / facade。
- 捕获模块错误并转换统一错误响应。

主要 route：

- `auth.py`：登录、登出、当前用户、token 生命周期。
- `setup.py`：初始化状态、初始化提交、setup token。
- `config*.py`：配置版本、配置项、配置校验。
- `admin*.py`：管理后台部门、用户、角色、知识库、文档、索引运维。
- `import*.py`：导入任务创建和查询。
- `knowledge.py`：普通用户知识库和文档读取。
- `query*.py`：非流式查询、流式查询、历史会话。
- `audit.py`：审计、查询日志、模型调用日志。
- `health.py`：live / ready。

### `api/schemas`

职责：

- 定义 API DTO。
- 区分 admin / public / setup / query / config 等接口模型。
- 不依赖 `modules/*`。

### `api/presenters`

职责：

- 将 service 返回值裁剪成展示模型。
- 转换状态、名称、列表摘要字段。
- 不查库、不鉴权、不调用 provider。

当前 presenter：

- `admin.py`
- `audit.py`
- `knowledge.py`
- `query.py`

## 领域模块

### `modules/auth`

职责：

- 账号密码认证。
- 密码哈希和校验。
- JWT access / refresh token。
- 当前用户上下文加载。
- 用户自助改密。

边界：

- 不承担业务权限决策。
- 不直接处理知识库或文档可见性。

### `modules/setup`

职责：

- setup mode 状态判断。
- 初始化 payload 校验。
- 企业、部门、管理员和内置角色初始化。
- 初始化配置发布。
- Secret 初始化。
- ServiceBootstrap 启动门禁。

边界：

- setup JWT 只能访问 setup 相关接口。
- 初始化成功后普通业务 API 必须依赖 active config。

### `modules/config`

职责：

- 配置版本读写。
- 配置项编辑。
- JSON Schema 校验。
- 依赖校验。
- active config 发布。
- 配置缓存和配置发布后失效。

边界：

- 业务模块只能通过 ConfigService 获取 active config。
- 不应回退读取 `.env` 业务配置。

### `modules/secrets`

职责：

- Secret Store。
- secret ref 解析。
- secret value 加密和解密。

边界：

- 不在日志、响应、审计中输出 secret value。
- Secret Store master key 丢失时不能解密既有 secret。

### `modules/admin`

职责：

- 管理后台业务编排。
- 部门、用户、角色、知识库、文件夹、文档、文档版本、索引版本等管理。
- 管理侧权限 guard。
- 管理侧审计事件。
- 索引运维任务创建入口。

边界：

- 管理列表接口必须后端分页、筛选和权限过滤。
- 管理详情接口必须重新鉴权。

### `modules/permissions`

职责：

- RBAC scope 判断。
- 部门作用域和知识库作用域判断。
- 文档可见性策略。
- PermissionFilter 构建。
- candidate gate 权限二次过滤。
- 管理侧权限校验。

边界：

- 不依赖 LLM。
- 不读取模型回答。
- 所有权限相关改动必须 fail closed。

### `modules/knowledge`

职责：

- 普通用户知识库列表。
- 文档浏览。
- source / chunk 读取。
- 引用来源读取前的权限检查。

边界：

- source 详情不能因为列表可见就默认可见。
- 文档原文读取必须重新鉴权。

### `modules/import_pipeline`

职责：

- 导入任务创建和命令服务。
- 上传校验。
- Worker 任务领取、锁接管和阶段执行。
- 文档版本写入。
- parse、clean、chunk、embed、index 阶段编排。
- 任务失败和重试。

边界：

- Worker 阶段必须幂等。
- 外部 IO 不应长时间占用数据库事务。
- draft index 发布前不可查询。

### `modules/indexing`

职责：

- draft vector 写入。
- index version 发布。
- 权限 payload 构建和刷新。
- collection health。
- Qdrant snapshot。
- 索引清理和重建任务。

边界：

- draft vector points 不得作为 active 查询候选。
- Qdrant 是派生状态，PostgreSQL 是索引版本事实源。

### `modules/query`

职责：

- 查询请求编排。
- 可访问知识库自动搜索。
- 多 query 召回。
- 向量召回、关键词召回、融合、rerank。
- candidate quality gate。
- context builder。
- LLM 调用。
- citation 校验。
- 查询日志和模型调用日志关联。
- SSE 流式准备和输出。

边界：

- 查询候选进入上下文前必须通过权限和状态过滤。
- citation unauthorized 必须抑制原答案。
- 降级必须返回可读原因。

### `modules/query_rewrite`

职责：

- Query Rewrite。
- 联合问题拆分。
- 生成检索 query。
- provider 不可用时使用 fallback。

边界：

- rewrite 只影响检索 query，不应改变用户原始问题事实。
- 失败时必须可降级到原始问题。

### `modules/retrieval`

职责：

- 检索候选模型。
- 向量 retriever adapter 抽象。
- rerank 抽象。
- candidate quality gate。
- MMR 和融合相关能力。

边界：

- 不直接处理 HTTP。
- 不做最终权限决策，只接收权限过滤条件并配合 query service 二次校验。

### `modules/context`

职责：

- 构建 LLM 上下文。
- 控制最大 chunk 数量和字符预算。
- 从对象存储读取完整 chunk 正文。
- 对缺失正文回落 preview。

边界：

- 只使用已通过权限校验的候选。

### `modules/answer`

职责：

- LLM prompt 组装。
- Chat provider 调用。
- 流式 token 输出。
- 无模型时的可控降级回答。

边界：

- 不做权限决策。
- 不应输出无 citation 支撑的最终答案。

### `modules/models`

职责：

- OpenAI-compatible chat client。
- embedding client。
- rerank client。
- HTTP 请求封装。
- provider 错误码规范化。

边界：

- 不读取数据库。
- 不处理业务权限。
- 不在日志中输出完整 prompt 或 secret。

### `modules/audit`

职责：

- 审计日志写入和读取。
- 查询日志读取。
- 模型调用日志读取。

边界：

- 列表只返回摘要。
- 详情按权限读取。
- 不展示完整 prompt 或文档原文。

### `modules/storage`

职责：

- 按 active config 构建对象存储。
- 封装对象读写。

边界：

- route 层不得直接 build object storage。

## Adapter

`adapters` 封装外部系统差异，包括 Qdrant、对象存储或其他 provider adapter。

职责：

- SDK / HTTP 协议适配。
- 超时、认证、基础响应解析。

禁止：

- 查业务数据库。
- 依赖业务 service。
- 构造 API response。

## Worker

Worker 入口位于：

```text
apps/worker/app/main.py
```

职责：

- 初始化运行时。
- 按轮询间隔领取任务。
- 执行 import pipeline。
- 记录任务状态。

Worker 不提供 HTTP API，不承担前端交互。

## 修改模块时的检查点

新增或修改模块能力时应检查：

- route 是否只做 HTTP 编排。
- service 是否承担事务和业务规则。
- repository 是否只做 SQL。
- presenter 是否只裁剪展示字段。
- 权限是否在 service 或 Permission Service 中完成。
- OpenAPI、权限矩阵、审计事件和测试是否同步。
