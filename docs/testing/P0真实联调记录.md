# P0 真实联调与查询回归记录

本文记录 P0 主链路在真实 API、Worker、MinIO、Qdrant 和模型 provider 上的验收方式。目标不是替代单元测试，而是固定“上传 -> Worker -> 索引 -> 查询 -> citation -> 审计”的真实环境证据。

## 1. 执行前提

- API 已启动，并且 `/health/ready` 返回 `ready`。
- Worker 已启动；上传任务不应长期停留在 `queued`。
- MinIO / S3-compatible bucket 可写可读。
- Qdrant collection 可写入、可召回。
- embedding、rerank、LLM provider 地址与 active config 一致。
- smoke / regression 用户可登录，并至少能访问一个已有 active index 的知识库。

## 2. 固定命令

生成 P0 smoke 脱敏执行记录：

```bash
LITTLE_BEAR_SMOKE_USERNAME=<username> \
LITTLE_BEAR_SMOKE_PASSWORD=<password> \
LITTLE_BEAR_SMOKE_KB_ID=<optional_kb_id> \
LITTLE_BEAR_SMOKE_REQUIRE_CITATIONS=1 \
make PYTHON=.venv/bin/python smoke-p0-record
```

默认记录输出到：

```text
artifacts/p0-smoke-latest.json
```

执行查询回归数据集：

```bash
LITTLE_BEAR_REGRESSION_USERNAME=<username> \
LITTLE_BEAR_REGRESSION_PASSWORD=<password> \
LITTLE_BEAR_REGRESSION_KB_ID=<optional_kb_id> \
LITTLE_BEAR_QUERY_REGRESSION_DATASET=docs/examples/query-regression.p0.jsonl \
make PYTHON=.venv/bin/python query-regression-p0
```

默认记录输出到：

```text
artifacts/query-regression-latest.json
```

`artifacts/` 已加入 `.gitignore`，记录文件可以保存在本机或 CI artifact 中，不应提交包含业务数据的真实验收记录。

## 3. 查询回归数据集格式

数据集使用 JSONL，每行一个 case。最小字段：

```json
{"case_id":"hr_leave_policy","query":"如何申请年假？","min_citations":1,"allow_degraded":false}
```

常用字段：

- `kb_ids`：指定知识库列表；不填时使用 `LITTLE_BEAR_REGRESSION_KB_ID`，再不填则使用当前用户可访问的第一个知识库。
- `mode`：`answer` 或 `search`。
- `top_k`：召回候选数量。
- `include_sources`：是否返回 citation。
- `min_citations`：最少 citation 数量。
- `allow_degraded`：是否允许 rerank / LLM 降级后仍通过。
- `expected_answer_terms`：答案中必须出现的短语。
- `expected_citation_title_terms`：citation 标题中必须出现的短语。
- `expected_doc_ids`：citation 至少命中其中一个文档 ID。
- `run_stream`：是否额外验证 SSE `metadata` / `done` / citation 事件。

`docs/examples/query-regression.p0.jsonl` 只是样例。真实验收时应复制一份业务数据集，例如 `docs/examples/query-regression.local.jsonl`，把问题、预期 citation 和必要关键词替换为当前企业知识库的内容。

## 5. 通过标准

- P0 smoke：setup、ready、login、current user、knowledge bases、documents / chunks、non-stream query、SSE query、logout 全部通过。
- 查询回归：所有 JSONL case 通过；生产验收数据集不应长期使用 `allow_degraded=true`。
- 上传联调：Import Job 最终为 `success/finished` 或有可解释的 `partial_success`；文档为 `active/indexed`；chunks、keyword index、Qdrant points 与 document version 可对账。
- 权限验收：无权限用户无法看到知识库、文档和 citation；权限收紧后旧用户不能通过旧索引或旧缓存命中。

## 6. 失败定位

- `queued`：优先检查 Worker 是否启动、`WORKER_ID` 是否唯一、数据库锁是否过期。
- `running` 卡住：检查 Worker 日志、`import_jobs.stage`、外部 provider 超时和对象存储读取错误。
- `LLM_PROVIDER_HTTP_ERROR`：检查 active config 中 LLM provider base URL、模型名、API key secret 和 provider 兼容格式。
- citation 数为 0：确认文档已 active/indexed、用户有知识库和文档权限、查询问题能命中已导入内容。
- 回归 case 降级：检查 rerank / LLM provider 可用性；如果只想验证检索，可以临时设置 `allow_degraded=true`，但不能作为生产质量验收结论。
